# 安卓定时任务 App 开发计划

> 项目名（暂定）：autoTask
> 一句话定位：低内存、防后台清理的安卓定时任务 App —— 到点自动打开指定 App，失败自动重试并记录日志。

---

## 1. 产品功能

| 功能 | 说明 |
|---|---|
| 定时任务 | 用户创建任务：选择目标 App + 触发时间，支持单次 / 每日 / 每周指定星期 / 工作日 / 节假日 / 自定义智能模式 |
| 自动打开 App | 到点后自动拉起目标 App 到前台 |
| 失败重试 | 打开失败自动重试（默认最多 3 次，间隔递增 30s → 1min → 2min） |
| 日志 | 记录每次执行：成功 / 失败原因 / 重试过程，App 内可查看 |
| 防后台清理 | 前台服务常驻 + 引导用户完成系统设置（见 §3.4） |
| 低内存 | 单进程、轻量依赖、APK 目标 < 10MB |

---

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Kotlin | 现代、官方推荐 |
| UI | 原生 View + Material Components（XML） | 比 Compose 更轻，内存/体积更小，符合低内存目标 |
| 最低版本 | minSdk 26（Android 8.0） | 覆盖绝大多数存量设备，且 8.0 起前台服务/通知 API 稳定 |
| 目标版本 | targetSdk 34（Android 14） | 满足主流商店要求；Android 15 适配作为后续项 |
| 调度 | `AlarmManager.setExactAndAllowWhileIdle` | 精确闹钟，Doze 模式下仍可触发；无需额外库 |
| 触发 | 静态注册 `BroadcastReceiver` + `RECEIVE_BOOT_COMPLETED` | 支持开机后恢复所有任务 |
| 常驻执行 | 前台服务（`dataSync` 类型，Android 14 必需声明类型） | 提高进程存活率 |
| 拉起 App | `startActivity` + `SYSTEM_ALERT_WINDOW`（悬浮窗）权限 | Android 10+ 从后台启动 Activity 的唯一可靠豁免途径 |
| 前台检测 | `UsageStatsManager` | 判断目标 App 是否真的到了前台（判定成败） |
| 存储 | 原生 SQLite（自写轻量 DAO） | 比 Room 少 ~2MB 体积、更省内存 |
| 日志 | 自研轻量文件日志器（环形覆盖，上限如 1MB/任务） | 不引入重型日志框架 |
| 依赖 | 仅 AndroidX 核心 + Material | 不引入 WorkManager / Play Services / 图片库 |

## 3. 核心机制设计

### 3.1 调度引擎
- 任务入库后，把下一次触发时间注册到 `AlarmManager`（`setExactAndAllowWhileIdle`）。
- 到点 → `TaskAlarmReceiver` 收到广播 → 交给 `TaskExecutor` 执行。
- 周期任务：执行完毕后计算下一次时间并重新注册。
- 开机广播（`BOOT_COMPLETED`）→ 重建所有待执行任务的闹钟。
- 时间变更（`TIME_SET` / `TIMEZONE_CHANGED`）同样重建。

**调度模式（ScheduleMode）**：

| 模式 | 含义 | 下一次触发计算 |
|---|---|---|
| ONCE 单次 | 指定时刻执行一次 | 执行后任务自动完成 |
| DAILY 每日 | 每天固定时刻 | 次日同刻 |
| WEEKLY 每周 | 勾选若干星期 | 下一个被勾选的星期 |
| WORKDAY 工作日 | 每个工作日执行（含调休补班日，跳过法定节假日） | 基于节假日日历推算 |
| HOLIDAY 节假日 | 每个节假日执行（含周末，不含调休补班日） | 基于节假日日历推算 |
| SMART 自定义智能 | 用户勾选规则组合（如"仅工作日 + 指定时段"） | 按规则组合推算 |

**节假日日历模块**：内置中国法定节假日 + 调休数据（JSON asset，按年打包 2025/2026…）。工作日判定 = 周一~五 ∪ 调休补班日 − 法定节假日；节假日判定 = 法定节假日 ∪ 普通周末 − 调休补班日。数据支持 App 内手动或可选联网更新（轻量 HTTP GET 静态 JSON，更新失败不影响主功能）。

### 3.2 打开 App（本项目最大技术难点）
- 正常路径：解析目标 App 的 launcher Activity 后 `startActivity`。
- **Android 10+ 后台启动限制**：从后台直接 startActivity 会被系统拦截，必须持有**悬浮窗权限**（`SYSTEM_ALERT_WINDOW`）才能豁免。
- 因此：App 内置权限引导，任务执行前检查悬浮窗权限；未授权时该任务记录"权限缺失"失败并给出引导。
- 备选方案（留作 Plan B）：AccessibilityService 辅助拉起，更稳但内存占用更高，默认不用。
- 特殊情况：无 launcher Activity 或禁止外部启动的 App（部分系统应用）→ 判定失败并记日志。

### 3.3 重试机制
- 触发后尝试启动；**失败判定**：startActivity 抛异常，或启动后 5 秒内 `UsageStatsManager` 未检测到目标 App 进入前台。
- 重试策略：最多 3 次，间隔 30s / 60s / 120s（可配置）。
- 每次尝试都写入日志：时间、结果、失败原因、尝试次数。
- 全部失败 → 任务标记失败，等待下一次调度（周期任务）或手动重试。

### 3.4 防后台清理（多层方案）
1. **前台服务**：常驻低优先级通知（用户可手动隐藏通知渠道），进程优先级提升，普通清理杀不掉。
2. **电池优化白名单**：申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，避免 Doze 深度休眠。
3. **国产 ROM 自启动管理引导**：内置引导页，一键跳转小米 / 华为 / OPPO / vivo / 荣耀各自的"自启动管理"设置页（通过各自系统 Intent，需按厂商写适配表）。
4. **最近任务锁定**：引导用户在下拉最近任务时上滑锁定本 App。
5. **App 内"一键检测"页**：逐项检查——电池优化是否豁免、自启动是否开启、悬浮窗权限、通知权限，每项附"去设置"按钮和图文说明。

### 3.5 低内存实现要点
- 单进程，无 `largeHeap`。
- 服务执行完任务即降载（任务执行器只在触发窗口内活跃，其余时间只保留轻量调度广播，常驻前台服务保持空转最小内存）。
- 日志写入采用追加写 + 环形上限，不常驻大缓冲区。
- 启动时不预加载日志页数据，日志页进入时才查询。

## 4. 模块划分（单 App 模块）

```
app/
├── ui/            # 任务列表、任务编辑、日志页、设置引导页、权限检测页
├── task/          # 任务/执行记录模型 + SQLite DAO
├── schedule/      # AlarmManager 封装、TaskAlarmReceiver、BootReceiver、调度模式日期计算
├── calendar/      # 节假日数据（JSON asset + 可更新）+ 工作日/节假日判断
├── executor/      # TaskExecutor（执行+重试）、前台检测器（UsageStatsManager）
├── log/           # 文件日志器（环形覆盖）
└── permission/    # 权限引导工具：电池优化、悬浮窗、自启动、通知、使用情况访问
```

## 5. 开发里程碑

| 阶段 | 内容 | 产出/验收 |
|---|---|---|
| M0 | 环境搭建 + 项目骨架 | Android Studio 项目可运行，空白 App 装机成功 |
| M1 | 权限引导框架 | 悬浮窗 / 电池优化 / 通知权限引导可跳转 |
| M2 | 任务 CRUD + SQLite | 可创建/编辑/删除任务（含全部调度模式字段），数据持久化 |
| M3 | 调度引擎 | 单次/每日/每周到点触发；工作日/节假日智能模式正确推算（含调休）；杀进程+重启后任务恢复 |
| M4 | 打开 App + 前台检测 + 重试 | 到点能拉起目标 App；失败自动重试 |
| M5 | 日志模块 + 日志页 | 每次执行有完整日志，页面可查看/清空 |
| M6 | 防清理完整方案 | 前台服务常驻；自启动引导页（主流 5 大 ROM 适配） |
| M7 | 真机测试矩阵 | 覆盖 Android 10/13/14 + 小米/华为/OPPO/vivo/原生；测内存占用（目标：运行态 < 80MB，APK < 10MB） |

每阶段结束给出可运行版本，M3 之后即可边用边调。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| Android 10+ 后台启动 Activity 被拦截 | 悬浮窗权限引导 + 失败日志提示，Plan B AccessibilityService |
| 国产 ROM 强杀后台 | 前台服务 + 各厂商自启动引导页 + 最近任务锁定引导 |
| Doze 下闹钟延迟 | `setExactAndAllowWhileIdle` + 电池优化白名单 |
| Android 14 前台服务类型限制 | 声明 `dataSync` 类型并满足其使用条件 |
| 目标 App 无法被拉起（系统应用等） | 快速失败判定 + 日志说明原因 |
| 厂商系统更新改变设置页路径 | 引导页做"未知路径兜底"（打开系统设置总页） |

## 7. 待确认的决策点

1. ✅ **最低支持版本：Android 8.0（API 26）——已确认**
2. ✅ **调度模式：单次 + 每日 + 每周 + 工作日/节假日等智能模式（含节假日日历模块）——已确认**
3. 是否需要在任务里支持"传入参数/自定义 Intent"（高级玩法，默认不做）？
4. 是否计划上架应用商店（影响 targetSdk 与隐私合规要求）？
5. 包名 / 应用名是否用 `autoTask` 即可？
