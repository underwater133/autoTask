### ⚠️ 真机发现并已修复的 Bug

1. **新建任务默认停用**：编辑页"启用"开关在新建模式下未初始化（布局默认 unchecked），
   导致新建任务保存后不注册闹钟、永不触发。已修复（新建默认启用）+ 回归测试 `TaskEditActivityTest`。
   **教训：任何"新建 vs 编辑"共用的开关类控件，新建分支必须显式初始化。**

2. **vivo"后台弹出界面"拦截后台启动（重要！）**：
   回桌面/锁屏/切到其他应用后，任务触发时 `startActivity` **不抛异常但目标 App 实际未启动**
   （日志表现为"第 N 次启动成功，验证前台… → 前台验证超时"，100% 复现）。
   根因：vivo 的**"后台弹出界面"权限**默认禁止第三方 App 后台拉起 Activity，
   独立于悬浮窗权限（悬浮窗已授权也无效）；系统应用（如"设置"）不受限制。
   **解决**：i管家 → 应用管理 → 权限管理 → 后台弹出界面 → 允许 autoTask。
   配套改进：权限引导页新增"后台弹出界面"引导项；前台验证增加进程存活兜底；
   验证窗口 5s→8s。

3. **vivo 侧载应用（非商店安装）隐式启动被解析过滤**：
   `startActivity(MAIN/LAUNCHER + setPackage)` 报 `No Activity found`（shell 权限同样失败），
   即使 stopped=false、launcher filter 正常。对照：商店安装（installer=com.bbk.appstore）的隐藏应用可隐式启动。
   **解决**：输入"包名/Activity"显式组件格式（如 `com.launchrecorder.app/.MainActivity`），
   显式启动不经过 intent 解析，可绕过过滤（真机验证：LaunchRecorder 成功启动并记录）。
   配套：输入框支持相对类名（`.MainActivity` 自动补全包名）+ 单元测试。

### 📝 环境观察（vivo/iQOO 特性）

- 非精确闹钟（`AlarmManager.set`）在后台有 15~45s 延迟；精确闹钟（精确权限已授予）接近准时
- `adb shell input text` 中文/引号输入存在 shell 转义问题，自动化输入建议用 keyevent 逐键
- 设备默认授予 SCHEDULE_EXACT_ALARM（adb 渠道安装），`exactAllowReason=policy_permission`
